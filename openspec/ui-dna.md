## Design Tokens

All tokens live in the `@theme static` block of `apps/web/app/globals.css` (every token is emitted as a CSS variable) and are consumed as `var(--color-*)` or Tailwind utilities; hand-written component classes live in `@layer components` so utilities always win. Token **names** are stable; values change in that block only.

### Color Palette (neutral greys + lime)
- Canvas `--color-canvas`: `#060606` (page background, `html` and `body`)
- Panel `--color-panel`: `#181818` (surface: rail, dialogs, tiles, fields)
- Elevated `--color-elevated`: `#232323` (surface 2: compare slots, pills, hover surface)
- Default `--color-default`: `#272727`, hover `--color-default-hover`: `#2e2e2e` (surface 3: stat rows, chips, secondary buttons, close buttons)
- Card `--color-card`: `#202020` (content card `.efb-card`: radius 24, padding 16, inset 1 px `#ffffff0a` ring instead of a border)
- Segment `--color-segment`: `#474747` (current item of a segmented control)
- Line `--color-line`: `#292929`; hover / secondary border `--color-line-active`: `#434343`; tertiary `--color-line-tertiary`: `#5c5c5c`; separator `--color-line-separator`: `#ffffff0a`; shell edge `--color-shell-border`: `#ffffff14` (header bottom, tab bar border)
- Text primary `--color-text-primary`: `#fcfcfc`; muted `--color-text-secondary`: `#a0a0a0`; dim `--color-text-dim`: `#969696` — the lowest tone allowed for visible text **on a solid surface** (≥ 4.5:1 on the canvas and every surface up to `#2e2e2e`; the reference has no such token, the old `#6b6b73` failed 4.5:1 on panels)
- On-backdrop text `--color-text-on-backdrop`: `#d4d4d4` — secondary text drawn straight on the aurora strip or the detail tint (breadcrumb links and plain items, `.efb-subtitle`, the detail header's "dump max" note and position · style · condition line). The strip's teal end reaches a luminance of ~0.1 behind the breadcrumb, where `#a0a0a0` reads ~3:1 and the reference's `#fcfcfca6` breadcrumb 3.3–3.5:1; measured against the brightest pixel behind each line (text made transparent, every pixel of the line box sampled) on every public page and on a detail page of each card type at 1440 / 1024 / 768 / 390: ≥ 4.9:1 (low point 4.93:1: the "Home" crumb at 1024 on a Legendary card)
- Nav link `--color-nav-link`: `#ffffff8c`; active header pill `--color-nav-active`: `#f5ffff1a`
- Accent `--color-accent`: `#acf41a` (lime — primary actions, active states, the "Lab" in the wordmark); on-accent text `--color-accent-foreground`: `#080d02`; hover `--color-accent-hover`: `#99d919`; soft fill `--color-accent-soft`: `#adf7191f`; soft text `--color-accent-soft-foreground`: `#c2f879`; focus `--color-focus`: `#acf41a`
- Accent secondary `--color-accent-secondary`: `#06b6d4` (cyan — compare "B" side, informational; not a reference role)
- Skill boost `--color-skill-boost`: `#02fec5` (filled booster / boost chip)
- Warning `--color-accent-warn`: `#ffae5f`; danger `--color-accent-danger`: `#d83864` (fill / border — 3.95:1 on the panel, so **not for small text**); readable danger text `--color-danger-soft-foreground`: `#e9768b` (≥ 4.8:1 everywhere); success `--color-success`: `#6cc233`
- Fields `--color-field` `#181818`, hover `--color-field-hover` `#1c1c1ceb`, border hover `--color-field-border-hover` `#ffffff1a`, border focus `--color-field-border-focus` `#fafafa38`
- Overlays: backdrop `--color-backdrop` `#00000099`, dialog hairline `--color-overlay-hairline` `#ffffff4d` (inset 1 px), scrollbar thumb `--color-scrollbar-thumb` `#ffffff26`
- Position colours `--color-pos-fw` `#ff2e2e`, `--color-pos-mf` `#7dff1f`, `--color-pos-df` `#0099ff`, `--color-pos-gk` `#ffc300`

### Stat Tier Colors — single source `--color-tier-*`
- Max (100+): `#ff66cc` (a stat taken past 99 by boosters or a manager's +1; training alone stops at 99)
- Elite (90–99): `#01fec5`
- High (80–89): `#a8fe02`
- Mid (70–79): `#fbb206`
- Low (<70): `#ff2e2e`

The five hex values are declared once, in the `@theme` block of `apps/web/app/globals.css`. Every consumer references the tokens through `statTier` / `statTierClass` / `statTierBg` / `tierTextClass` / `tierBgClass` in `apps/web/lib/card-display.ts` (player-detail stat rows and pills, body-model values, best-fit pill, the Pitch Map rating cells, home OVR text) or the `.text-stat-tier-*` / `.bg-stat-tier-*` aliases in `globals.css`. Text on a tier pill: **black on every tier** (`statTierForeground` → `text-black`; `.efb-stat-row__value` sets `#000` too) — black on the low tier `#ff2e2e` reads 5.68:1 where white read 3.70:1 (efootbase-ui-redesign batch 4). Low-tier **text** uses `--color-tier-low-text` (`color-mix(in srgb, var(--color-tier-low) 80%, #fff)` ≈ `#ff5858`, derived from the token, no second hex) through `tierTextClass` / `statTierClass` / `.text-stat-tier-red`: `#ff2e2e` as text reads only 4.04:1 on the `#272727` stat rows and tiles, the derived tone 4.83:1 (5.7:1 on `#181818`); fills keep `#ff2e2e`. No component may hard-code a tier hex.

### Card-Type Accents — `--color-card-*`
One token per `CardType` (`STANDARD #64748b`, `LEGENDARY #fbbf24`, `TRENDING #06b6d4`, `SELECTION #fb923c`, `EPIC #8b5cf6`, `HIGHLIGHT #10b981`, `STRIKE_ARENA #ef4444`), mapped by `CARD_TYPE_COLOR_VAR`. Labels always come from the display table `CARD_TYPE_LABELS` in `@eflab/shared` — Standard, **Icons** (`LEGENDARY`), Trending, Selection, **Epic - Big Time** (`EPIC`), Highlight, Strike Arena, the reference's names (owner decision 2026-10-24; the seed checks the dump's own labels through the separate `CARD_TYPE_DUMP_LABELS`); the `/players` Card Type toggles follow `CARD_TYPE_FILTER_ORDER` (Standard, Selection, Icons, Trending, Highlight, Epic - Big Time, Strike Arena); raw enum names are never shown. "Big Time" and "Show Time" are pack campaigns, not card types (they are `EPIC` and `HIGHLIGHT`).

### Typography
- Primary sans: Inter via `next/font/google` (`var(--font-inter)`), system fallbacks. Inter only for visible labels — no monospace and no uppercase micro-labels, except keyboard chips (`.efb-kbd`, ⌘K / Esc / `/`) and code-like identifiers (card id).
- Card overlays: `eFootballStencil` (OVR) and `eFootballSans` (position/name) self-hosted from `apps/web/public/fonts/` — licence unknown, see CLAUDE.md "Known limitations".
- Numbers: tabular figures (`tabular-nums`).
- Headings have normal letter-spacing (base rule on `h1`–`h4`; never `tracking-tight` in new code).
- Scale (theme tokens → utilities `text-display` …, and classes):
  - page H1 36/40 bold (`text-display`), 30/36 below 768 (`text-display-sm`) — class `.efb-h1`;
  - `/players` H1 24/30 bold (`text-title`, `.efb-h1--compact`);
  - section H2 18/22.5 bold (`text-section`, `.efb-h2`);
  - subtitle 16/26, 14/20 below 768, max 768 px wide, in the on-backdrop tone (`.efb-subtitle`; it sits on the aurora);
  - labels and buttons 14/20, 500–600 (`text-label`);
  - captions 12/16 (`text-caption`); card style lines 11/13.75;
  - breadcrumbs 14/20 (`.breadcrumbs`: links and plain items — `.breadcrumbs__item--muted` — in the on-backdrop tone, current item white, the `aria-hidden` `›` separator dim: decorative, below 4.5:1 over the strip).

### Radius & Density
- Per component role (theme `--radius-*`, utilities `rounded-field` / `rounded-tile` / `rounded-panel` / `rounded-pill`): fields, search trigger, filter rows **12**; tiles, compare slots, palette, tab bar, sheet / drawer top corners **16**; content cards, the players rail, modal dialogs **24**; buttons and segmented controls **24** (pill); header links 8; stat rows 8; value chips 6; accent chip 16; skill / stat chips 8; toggles 10.
- 4 px spacing scale, compact padding suited to dense statistics.

### Shared component classes (`globals.css`, `@layer components`)
- **Buttons** `.button` + size `.button--sm` (32 px, padding 0 12, 14/20 500) / `--md` (40) + `.button--icon-only` (square: sm 32, md 36) + variant `.button--primary` (accent, hover `#99d919`) / `--secondary` (`#272727`, hover `#2e2e2e`, no border) / `--ghost` (transparent, hover `#272727`) / `--outline` (1 px `#292929`); radius 24; disabled / `aria-disabled` at 50 % opacity.
- **Chips** `.chip` + `.chip--lg` (28 px, padding 4/12, 14 px, 500, radius 16); `.chip--accent`, `.chip--default`.
- **Segmented control** `.segment` > `.segment__item` (32 px, padding 0 16, radius 24, 14/500, muted text; the current item — `aria-pressed` / `aria-selected` / `aria-checked` / `aria-current="page"` / `data-active` — is `#474747` with white text).
- **Field** `.field` (`--sm` 36, default 40, `--lg` 44 px; `#181818`, radius 12, transparent border → `#ffffff1a` on hover → `#fafafa38` on focus; placeholder `#a0a0a0`; the accent focus ring stays for keyboard focus) on an `<input>` or on a wrapper around `.field__input`.
- **Content surface** `.efb-card` (`#202020`, radius 24, padding 16, inset ring).
- **Modal variants** (`Modal.tsx` `variant`): `"dialog"` (default, `.efb-modal--dialog`: centred, 608 px wide — full width minus 16 px gutters on phones — up to 40 px from the viewport's top and bottom, radius 24, padding 24, title 16/500, the 32 × 32 close 16 px from the top-right corner, the body scrolling inside, an accent Done at the bottom right with no rule above it; used by the `/players` filter dialogs and the admin full-sync confirmation), `"sheet"` (`.efb-modal--sheet`: full-width bottom sheet, top radius 16, grab handle, full-width accent Done; the `/players` mobile filters and the detail page's mobile Progression sheet) and `"drawer"` (`.efb-modal--drawer`: bottom-anchored, 512 px wide — full width below 512 — top radius 16, padding 24, title 16/500, the close 16 px from the top-right corner so the header content spans the full width; the manager picker). All are the same native modal `<dialog>` (focus trap, Escape, backdrop click, focus return); initial focus goes to an element marked `data-autofocus` (the search field of the Nation / League / Team / Skills pickers and of the manager drawer — `Modal` focuses it right after `showModal()`, since React's `autoFocus` would fire before the dialog opens), otherwise to the browser's first focusable (Close); a dialog opened inside another (the manager drawer over the Progression sheet) closes only itself — `Modal` ignores a `close` event React re-dispatches from a nested dialog; panel `#181818` with an inset 1 px `#ffffff4d` hairline, a 32 × 32 round close button on `#272727` at the top right, backdrop `#00000099`. **Escape** (behaviour-parity A.2, B4): `Modal` handles it on the dialog's own keydown, so one press closes it even when a search field inside holds text (Chrome's `type="search"` used to swallow the first one); it acts only when no control inside handled it first (`defaultPrevented`: a Max Level draft reverting, an open tooltip / popover through the shared Escape layers), never during an IME composition, and only on the topmost dialog (the drawer over the sheet closes alone). **Pinned search**: the search field of the Nation / League / Team / Skills pickers and of the manager drawer stays at the top while the list scrolls (with its chips and the limit message under it). **Motion**: the sheet and the drawer slide in and out over 250 ms `cubic-bezier(.32,.72,0,1)` (the dialog closes at once — focus returns, the page is live — and the panel stays painted for the slide-out); instant under reduced motion. On the player page the manager drawer and the phone Progression sheet are loaded on first use (`components/build-simulator/deferred.tsx`: fetched on pointer-over / focus / press of their trigger, mounted on the first opening and kept; `Modal`'s `onShown` lets the sheet scroll to its categories once shown; when the chunk cannot be loaded the opening is given up, "Could not load — try again." is announced politely and focus stays on the trigger, whose next press retries) — not part of the route's first-load JavaScript.
- **Hit areas** `.hit-44`: on coarse pointers an invisible `::after` grows the tappable area to ≥ 44 × 44 px without changing the visible size; `.button` has the same rule. The base "≥ 44 px on coarse pointers" rule still applies to every other button / link (it skips `.button` and `.hit-44`). Never put `.hit-44` on an element that uses its own `::after` or a stretched-link pattern, and never on (or inside) an element with an `overflow` clip — the clip cuts the area: the pack titles keep their ellipsis on an inner `.efb-pack-title__text`, the dock strip on an inner `.efb-dock-strip__items`, and the dock's manager avatar rounds its art instead of clipping. Form fields cannot carry an `::after`: on coarse pointers text inputs and selects are ≥ 44 px tall (a `.field__input` inside a 36 px `.field` wrapper overflows it invisibly, so the drawn field keeps its size); the `.efb-range` sliders get a 44 px input box (negative margins, nothing moves) with the 16 px track painted on the track pseudo-element, and in a category row the label row sits above the slider and passes taps through its empty parts; the "About this build" `<summary>` and the Stats dialog's switch label carry `.hit-44`; the phone Progression sheet pads its panel by 6 px so the scrolling body does not clip the first row's areas. Verified at 320 / 390 with touch emulation by hit-testing every visible control at its centre ± 21 px (controls packed closer than 44 px — stat rows, chips, pagination — share the edge with the neighbour, by design).

### Backdrop
- One blurred strip at the top of every page, `linear-gradient(90deg, #34d9c8, #3b82f6 50%, #8b5cf6)` at opacity .54 with a 24 px blur, absolute in a clipped 640 px wrapper (scrolls with the page, never widens it), faded to the canvas by ~600 px; the old radial gradients and noise layer are gone. Measured at 1440×900: y = 70 → `#1a5b5a` / `#1a3560` / `#3a2c6c` at x = 20 / 720 / 1420 (reference `#1a615b` / `#1a355f` / `#3f2d6d`), y = 600 → `#060606`.
- Detail-page tint hook: an element with `data-card-tint="<CARD_TYPE>"` anywhere on the page lays a static tint of that card type's `--color-card-*` over the left half of the strip (`.efb-backdrop__tint`). The player detail page sets it on its root (`data-card-tint={p.cardType}`): a static tint per card type, because the reference's per-card tint source is unknown and R2 pixels are not sampled (design decision 3). Opacity **.15** (was .55): the light hues (Legendary gold, Selection orange, Highlight green, Trending cyan) at .55 lifted the backdrop behind the breadcrumb and the header line until even near-white text fell below 4.5:1 (Legendary 2.4:1); at .15 every header text in the on-backdrop tone reads ≥ 4.9:1 on all seven card types.

## Component Patterns

### Navigation Header
- Sticky `.efb-navbar`: 64 px bar (`h-16`, `max-w-6xl`, `px-4`, gap 16) + 1 px `#ffffff14` bottom edge = 65 px; translucent canvas fill with a 20 px blur and saturate 1.45 (the reference's own fill was not measured): **70 % at the top of the page** (only the aurora strip is under the bar; look unchanged, header text ≥ 6:1 there) and **85 % from the first scrolled pixel** — a scroll-driven animation (`animation-timeline: scroll(root block)`, `animation-range: 0 1px`) of the registered `--efb-navbar-fill` (`@property`; animating `background-color` itself left Chromium painting the 85 % end state after scrolling back to the top); a page too short to scroll keeps 70 % (inactive timeline → the property's initial value 70 %); browsers without scroll-driven animations get 85 % everywhere. 85 % is a contrast floor, not a look choice: over pure-white content the backdrop under the header text stays ≤ `#2b2b2b`, so the `#ffffff8c` links read ≥ 5.3:1 and the trigger's `#a0a0a0` text and ⌘K chip on its 5 % white fill ≥ 4.6:1 (with a flat 70 % bright skill artwork / card art scrolled under the bar pulled them to 4.27:1 and 3.44:1). eFootLab SVG wordmark (`EflabWordmark.tsx`, "eFoot" + lime "Lab", 32 px tall) linking home with `aria-label="eFootLab home"`.
- `nav[aria-label="Primary"]` links Players / Compare / Packs / Skills (`/wiki/skills`, active on every `/wiki/skills*` page), **visible from `lg` (1024)**: 14/20, weight 400, `#ffffff8c`, padding 6/12, radius 8; the active one (`aria-current="page"`) white on `#f5ffff1a` with an inset top highlight and a 1 px `#ffffff14` ring. No Home link (the logo is the home link).
- ⌘K search trigger from `lg`: `.efb-navbar-search-trigger` 208 × 32, radius 12, 5 % white fill, no border, search icon, "Search players", ⌘K chip (`aria-hidden`). Named by its text, "Search players" (no `aria-label` — the chip's visible "K" could not be in one without being read; change `a11y-names-and-card-league`), `aria-keyshortcuts="Meta+K Control+K"`. Below `lg`: a 36 × 36 ghost icon button (`data-testid="mobile-search-button"`, `aria-label` "Search players", the same `aria-keyshortcuts`, 44 × 44 hit area on touch). **No hamburger menu** — the tab bar carries the sections below `lg`.
- The trigger (and ⌘K / Ctrl+K — ignored while another modal dialog is open, so it never stacks over the compare picker or a filter dialog) opens the **search palette** (`components/search/SearchPalette.tsx`, also the compare picker): a named modal `<dialog>` (focus trap, Escape, backdrop click, focus returns to the opener) on `#00000099` with a 12 px backdrop blur; panel 576 px wide (full width minus 16 px gutters on phones; 358 at 390), radius 16, `#181818`, inset 1 px `#ffffff4d` hairline, top at `min(15vh, 135px)` (135 at 1440×900, as measured), at most 440 px tall with the results scrolling inside. ## Accessibility Baseline
- Contrast ≥ 4.5:1 for body text, 3:1 for large text.
- Visible focus style on every interactive element: a base rule gives links, buttons, fields and `[tabindex]` a 2 px accent outline with a 2 px offset on `:focus-visible` (zero specificity, so a component's own focus style wins); `.button`, `.segment__item`, `.field` and the tab bar items draw the same ring (tab bar items inset by 2 px); card tiles draw it as a 2 px border on `.pcb-tile:focus-visible::after`, 4 px outside the tile, so the scaled card never covers it.
- Dialogs (`<dialog>`) are named, trap focus, close on Escape and restore focus; buttons that open one carry `aria-haspopup="dialog"`; in-place disclosures (the home search combobox, the footer accordions below `lg`) expose `aria-expanded`.
- Landmarks: `header`, `nav[aria-label="Primary"]`, `nav[aria-label="Sections"]` (tab bar), `nav[aria-label="Breadcrumb"]` around each page's `ol[data-slot="breadcrumbs"]` (the last item `aria-current="page"`), `main#main-content`, `footer` with `nav[aria-label="Browse"]` / `nav[aria-label="Project"]` (column titles `h2`, so no heading level is skipped after a page that ends at `h1`); ≥ 44 px touch targets on coarse pointers — controls that keep a smaller visible size use `.hit-44` / `.button`'s invisible `::after` hit area.
- Skip links (`SkipLink.tsx`, `.efb-skip-link`): "Skip to content" is the first tab stop of every page (hidden until focused, then an accent pill with the focus ring above the sticky header) and moves focus to `main`; `/players` adds "Skip to filters" (from `lg`) and "Skip to results" as the first stops of `main`. Targets are containers without a ring (`.efb-skip-target`, 96 px scroll margin) that get `tabindex="-1"` from the skip link only while they hold its focus (a permanent one would make a click on blank page space focus `main` and keep a popover's outside click from returning focus to its trigger); no `#hash` is written.
- Every data request that fails shows its failure with Retry — also offline: requests are made and fail (TanStack `networkMode: "always"`, no retry while offline) instead of pausing, the message says "You appear to be offline", and the query reloads by itself when the browser is back online.
- Information is not left in a `title` alone: the detail header pill's explanation is visually hidden text; the compare Swap / Copy link reasons ("Pick two players …", "Pick a player …") are `aria-describedby` descriptions of the `aria-disabled` buttons.
- **Label in Name** (WCAG 2.5.3, change `a11y-names-and-card-league`): a link's or button's accessible name contains the text it shows, in order — prefer a name from the content (visible text + visually hidden words); an `aria-label` is built from the visible pieces in their order (extra words before or after them only), visible pieces in separate elements are kept apart by a space text node, visible `aria-hidden` text counts as shown, and shortcuts go in `aria-keyshortcuts`. Checked with axe-core 4.14 (`label-content-name-mismatch` on): 0 violations on the public pages at 1440 and 390.
- No horizontal page scroll from 320 px up (Pitch Map, pagination, compare bars and popovers use container-relative sizing; `body { overflow-x: hidden }` is a safety net only).

## Anti-Patterns (What We Deliberately Avoid)
- No Three.js or WebGL for cards; no layered runtime composition (one image + overlays).
- No efootbase/efhub branding, icons or build ids; no copied third-party sidebar content.
- No numbers the data does not provide (rarity tier words, Position Training, In-Match Roles, manager tactics, form offsets — see the pending register; the skill page's rarity rank is a count over stored holders, not a score); progression numbers come from the recovered training rules and efootbase's own band table, manager effect and overall formula (no "~", no anchor); the line next to the overall names the build status and the setting, and the panel's "About this build" disclosure names the verification and holds the limits note (what is checked only in bulk and what is not modelled), in neutral wording.
- No AI-landing-page tropes (gradient text, neon auras, tilted casino cards, emoji chips).
- No raw enum names or snake_case data in the UI.
- No prices for packs.
- No calls to key-gated third-party APIs from the web app.
