## Why

A browser survey of the reference site on 2026-10-23 (28 page loads; kept in the outside-repo survey folder, sections S1–S3, with S4 listing what is still unmeasured) showed that many eFootLab functions look like the reference but behave differently: build state is lost on reload, managers are not remembered, the second booster cannot be chosen, compare is a base-stat table instead of a two-build tool, search ignores pack names, `/players` sorts and filters by other rules, and the skills wiki lives at another URL. The owner asked for the functions and their logic to match the reference exactly, without guessing; this change implements only what the survey verified (at least two independent checks) and records everything else as pending.

## What Changes

- **Tooltip timing**: hover previews open after about 500 ms and close about 100 ms after the pointer leaves (was 1500 ms / 500 ms); moving straight to the next trigger and keyboard focus open at once.
- **Build in the card URL**: the player page writes its build to the query string (`sho pas dri dex lbs aer def gk1 gk2 gk3`, `pts=0`, `mp`, `mgr`, `b1`, `b2`, `b2l`, `ml`) with `replaceState`, and restores it from a link. An over-budget or out-of-range link is clamped, the URL is corrected and the correction is announced (the reference clamps silently — not copied).
- **Remembered manager**: a chosen manager is stored in the browser (`eflab:selected-manager`) and pre-selected on every card; deselecting it (choosing it again or "Clear") returns Manager Proficiency to 90 and forgets it. A `mgr` link selects a manager without storing it.
- **Adjust popover**: a stat row and a category-strip item open the same popover holding only the category's − / value / + controls and a 0–25 slider; the per-stat breakdown moves to a "Stat breakdown" list in "About this build". Jumping keeps both Aerial Strength and Goalkeeper 1 (the reference offers only Goalkeeper 1 — not copied). **BREAKING (UI)**: clicking a strip item no longer pins the highlight; panel category labels still pin.
- **Boosters**: cards without their own Booster 2 get a "Select Booster" slot that opens a "Select second booster" drawer with the 29 basic "+1" boosters (from the committed booster fixture, matched 29/29 to the reference); a card's own Booster 2 is a fixed pill that toggles off/on; a Trending card's Booster 1 cycles +3 → off → +1 → +2 → +3.
- **Level-cap-1 cards**: Highlight cards with a level cap of 1 get a Max Level slider 1–80 (`ml`) that starts empty and trims the last categories first when lowered; Trending cards get a "Build" panel (manager and proficiency, no categories). Both now include the proficiency bonus like the reference. Other level-cap-1 types keep the current note (not measured). Lowering the Max Level of any card now trims points from the last categories (the reference's rule) instead of resetting the build to zero.
- **Search**: one server rule for the palette, the home search and the compare picker — at least 3 characters, card name **or pack / campaign name**, ordered by max overall then newest id, 12 rows per page with more on scroll; within each page, names with a word starting with the query come first. The palette activates its first row while typing and Enter opens it. Debounce 200 ms (palette, home) and 500 ms (`/players`). **BREAKING (ranking)**: the five-tier ranking and the fuzzy tier are removed.
- **`/players`**: High to low / Low to high sort by max overall; Trending and Top rated are hidden (no community data) and New cards becomes the default; Position filters by registered position; Playing Style accepts several styles (main styles OR, AI styles AND); the Team dialog lists every team under league headings and is no longer narrowed by League; Nation lists ten fixed nations first; Reset keeps search and sort; removable active-filter chips; row count badges; the reference's empty-state copy. URL uses the reference's names and encodings where verified (`pos=<index>`, `condition`/`form`/`wfa`/`wfu` 0-based repeated, `playingStyle` repeated with `p_*` AI keys, `skill=s_*`, `team=<name>`) and still reads every older eFootLab link. **BREAKING (URL meaning)**: a single-value `form`, `wfa` or `wfu` from an old eFootLab link now means one star more (0-based); `sort=highest`/`lowest` now mean max overall. 72 cards per numbered page and the count line stay (owner decision).
- **Home and packs**: home "Latest Packs" shows the first three packs of `/packs`, with plain titles and no arrow buttons; `/packs` keeps the stored order (current packs newest first, then spotlights) and adds a "Last updated" chip (age of the newest card release); eFootLab's own counts and `/packs/[slug]` pages stay.
- **Compare as a two-build tool**: `?left=&right=` with per-side builds (`l_*`/`r_*`, `l_mgr`/`r_mgr`, `lb`/`rb`), Max OVR / Reset / Select Manager per side, no proficiency bonus without a manager, the same card allowed on both sides, Remove keeps the other card in place, a value-pill table with a difference on both sides, Overview / Skills / Body Model sections, and position tiles from the build. `?ids=` links still work. The radar is unchanged (two axes unmeasured).
- **Skills wiki**: `/wiki/skills` and `/wiki/skills/<slug>` (slug from the stored skill key, matching all 67 reference slugs); `/skills` and old slugs redirect with 308; no "Other" section; tiles show the leader card; the skill page shows a rarity rank, the leader card and the 12 next best players (one card each) without pagination, with "Show all" into `/players?skill=s_*`.
- **Card-type display labels** (owner decision 2026-10-24): the UI shows "Icons" and "Epic - Big Time" like the reference, with the Card Type toggles in its order; the seed keeps checking the dump's own labels through a separate table.
- **Documentation** of every pending measurement, data-dependent item and reference oddity not copied (ui-dna, CLAUDE.md).
- Not in this change: any database write or migration, any request to the reference site, Form A–E, Position Training, weak-foot and stamina chips, In-Match Roles, radar SHT/DRI, skill type chips and tier words, "Works well with", community features.
