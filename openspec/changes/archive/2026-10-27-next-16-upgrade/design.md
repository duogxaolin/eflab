## Context

See proposal.md. Facts from the research of 2026-10-27 (official Next 16 guide, release notes, a read of the `next@16.4.3` and `@next/env@16.4.3` packages; nothing run on the repo): `next@16.4.3` is `latest`, needs Node ≥ 20.9 (the repo uses 22) and accepts the installed React 19.3; the code base already satisfies the 16 breaking changes (no `middleware`, all `params` / `searchParams` Promises, no `cookies()` / `headers()`, no `next/image`, no custom `webpack`, no `next lint`, no parallel routes). Open risks are observed behaviour, not code: the production bundler changes from webpack to Turbopack, the router / prefetch layer was rewritten (the app's `/players` echo adoption depends on router timing), Next rewrites `tsconfig.json` and `next-env.d.ts`, and the "First Load JS" column no longer exists. The vendored React in 16.4.3 (`19.3.0-canary-278794d7-20261002`) contains the cursor reset in `replayBeginWork` for host components that the 15.5 React (`19.2.0-canary-0bdb9206-20250818`) lacks — the cause of the #418 documented in change `efootbase-function-parity` D13.

## Goals / Non-Goals

**Goals:** a patched, current framework; the hydration root cause gone with `PageSlot` removed only on proof; no change in behaviour; honest bundle-size numbers.
**Non-Goals:** React Compiler, Cache Components, Server Actions, image optimisation, any feature or data change.

## Decisions

### D1. Two steps, each its own commit
Step 1: `next@15.5.28` (security patch; same React; `PageSlot` stays). Step 2: `next@16.4.3`. Step 3: remove `PageSlot` only if the D4 proof passes. A failed step is reverted without losing the earlier ones.

### D2. Work in a git worktree, check builds in `.next-check`
All builds / browser checks use `NEXT_DIST_DIR=.next-check` on ports 4200 / 7200 (the 16 build lock is per `distDir`; a check build runs next to the served `.next`). The owner's :3000 / :4000 are restarted by port only at the very end.

### D3. Edits (no codemod)
`next dev -p 3000` (no `--turbopack`); `tsconfig.json` `jsx: react-jsx`; `next.config.ts`: `agentRules: false`, `images.unoptimized: true` (and the R2 `remotePatterns` removed with it) after confirming `/_next/image` then answers 4xx for any URL — if it does not, keep `remotePatterns` and report; nothing else changes (no `turbopack`, `cacheComponents`, `reactCompiler`, `experimental`). `next-env.d.ts` stays tracked (lowest risk; a fresh clone type-checks after one build / `next typegen`); it will flip between dev, build and check runs and is restored after check builds as today — with `git checkout --` once this change is committed; before the commit that command would revert this change's own edits to `tsconfig.json` / `next-env.d.ts`, so the step's saved patch (kept outside the repo) is re-applied instead. The codemod is not run (nothing for it to change; it would also touch the lockfile).

### D4. Hydration proof (method of D13 of change `efootbase-function-parity`)
Production build (Turbopack) without `PageSlot`; one long-lived warm browser context; the `app/error` chunk held back ~20 ms via request routing; ≥ 250 loads over `/`, `/compare`, `/wiki/skills`, `/packs`, `/players`, a player page, a skill page at 320 / 390 / 1440 px; a patched copy of the client react-dom chunk counts replays of a suspended host fiber under `<main>` and hydration mismatches. Required: replays > 0, mismatches 0, console #418 0. Positive control: the same harness on 15.5.26 without `PageSlot` must show #418 (5/240 plain, 33/96 with the chunk held were the 2026-10-24 numbers). Because Turbopack chunks differently, a clean run with 0 replays is inconclusive; the harness then forces suspension (longer hold) until replays occur or the proof is declared inconclusive and `PageSlot` stays.

### D5. Bundle metric
Metric: gzip bytes of every JS response a route loads in a fresh browser context at 1440 px (Playwright response sizes + `content-encoding` gzip of the body), on 15.5.26 and 16.4.3, same machine, same data. `diagnostics/route-bundle-stats.json` (uncompressed, Turbopack only) is recorded beside it. CLAUDE.md keeps the old webpack figures as historical and states the new ones with the definition.

### D6. Verification list (= the research's checklist)
Redirects (`curl -I`), headers (security + admin), route types after a clean state / dev / check build, env precedence (three sources), fonts (Inter computed font + `--font-inter`, Konami `@font-face` 200), CSS parity (screenshots, Tailwind `@theme static` tokens), build log and route table, `next dev` writes (`.next/dev` only, no `AGENTS.md`), router / history behaviour (rapid filter toggles, Back / Forward, header search while on `/players`, `?page=0`, card-page `replaceState` + reload, compare restore, `/wiki/skills` params), server pages (404s, `generateMetadata` titles, `permanentRedirect` with query), admin login + dashboard with the API up, `pnpm test`, axe 4.14 on three pages (baseline 0).

## Risks / Trade-offs

- [Turbopack output differs from webpack] → screenshot parity and asset checks; fallback `next build --webpack` is documented but not adopted unless a real defect appears.
- [Router rewrite breaks `/players` echo adoption] → run the scripted behaviour QA on both versions and diff the URL / state transcripts.
- [Hydration proof inconclusive] → `PageSlot` stays (inert); the change still ships the upgrade.
- [Tracked-file churn] → documented; restore after check builds.
- [Size grows] → report > 10 %; Turbopack usually shrinks.

## Migration Plan
